# 마중 화면 동작 정의

작성일: 2026-10-27
기준: M01 차량 앱 화면 흐름도(최신), M02 동승자 모바일 웹 흐름도, M03 위치 변경 흐름, 디자인 캔버스 "마중 화면 UI"
표기: [P] = Pleos API, [S] = 우리 서버 API, [K] = 카카오맵 API, [확인] = 10/28 설명회에서 확인할 것

## 화면 목록

| 구분 | 화면 |
|---|---|
| 차량 앱 | C01 홈 · C02 목적지 입력 · C03 모드 선택 · C04 장소 추천·선택 · C05 링크 전달 QR · C06 장소 이동 · C07 도착 완료(모드별 3장) · C08 장소 평가 · C09 목적지 기록 |
| 차량 앱 · 위치 변경 | C10 위치 바꾸기 · C11 가족 제안 받기 · C12 변경 결과 알림(바뀜 / 거절 / 무응답 / 취소) |
| 동승자 웹 | W01 방문 카드 · W02 운전자 제안 받기 · W03 종료 |
| 동승자 웹 · 위치 변경 | W04 위치 바꾸기 · W05 변경 결과 알림 · W06 문자 알림 |

흐름: C01 → C02/C09 → C03 → C04 → (픽업하기만 C05) → C06 → C07 → C08 → C01. 흐름도는 M01 최신본 기준.

## 모드 3가지

| 모드 | C04에서 고르는 것 | 링크 전달(C05) | C07 버튼 |
|---|---|---|---|
| 픽업하기 | 픽업 장소 (+ 날씨) | 있음 | 탑승 완료 |
| 그냥가기 | 목적지 근처 주차장 (+ 날씨) | 없음 | 주차 완료 (층 선택) |
| 내려주기 | 하차 장소 (+ 날씨) | 없음 | 하차 완료 |

동승자 웹(W01~W06)과 위치 변경(C10~C12)은 **픽업하기에서만** 쓴다.

## 공통 규칙

| 항목 | 정의 |
|---|---|
| 주행 상태 | `CarUxRestrictionsManager`로 판단. 제한 켜짐 = 주행 중, 꺼짐 = 정차 중. 화면 오른쪽 위 칩으로 표시 |
| 주행 중 | C06 · C07 · C11 · C12만 표시(장소 + 버튼 하나). 나머지는 "정차 후 이용해 주세요"로 가리고 입력 값은 보관 |
| 내비 요청 | [P] `requestRoute` 콜백 성공 후에만 "내비 안내 중". 실패나 10초 무응답이면 "내비에 넣지 못했어요 · 다시 시도" |
| 서버 요청 | 요청 ID를 붙여 보냄. 응답이 없으면 같은 ID로 다시 보냄(두 번 처리 안 됨) |
| 버전 | 방문마다 버전 번호. 만날 곳이 바뀔 때마다 +1. 옛 버전 기준 요청은 서버가 거부 |
| 통신 끊김 | "서버 연결 끊김 · 14:40 기준" 띠. 마지막으로 확정된 장소는 계속 표시 |
| 앱 재시작 | [S] 진행 중 방문 조회 → 있으면 그 단계 화면으로. 지난 내비 명령은 자동으로 다시 실행하지 않음 |
| 뒤로 | 왼쪽 위 뒤로 버튼. C04에서 장소를 정한 뒤로는 뒤로 대신 "방문 취소"(확인 창) |

## 차량 앱

### C01 홈
| 구분 | 내용 |
|---|---|
| 진입 | 앱 실행, C08 평가 완료 · 건너뛰기 후 |
| 표시 | "어디로 갈까요?", 목적지 입력 칸, 최근 간 곳(최대 3), 진행 중인 방문, 목적지 기록 버튼 |
| 동작 | 목적지 입력 → C02 / 최근 간 곳 → 그 장소로 C03 / 목적지 기록 → C09 / 진행 중인 방문 → 그 단계 화면 |
| 시스템 | [S] 진행 중 방문 조회, 최근 방문 3건 조회 |
| 예외 | 서버 안 되면 최근 간 곳 숨김, 목적지 입력만 |
| 주행 중 | 가림 |

### C02 목적지 입력
| 구분 | 내용 |
|---|---|
| 진입 | C01 목적지 입력 |
| 표시 | 검색 칸(자동 포커스), 결과: 이름, 주소·거리, 태그(승하차 구역 확인됨 / 실내 주차) |
| 동작 | 결과 선택 → C03 |
| 시스템 | [S] 시설 검색, [P] `getCurrentLocationInfo`로 거리 계산 |
| 예외 | 확인 안 된 시설은 흐리게 "일반 길안내만 가능" → 선택하면 그냥가기만 가능 / 결과 없음: "아직 준비된 시설이 없어요" |
| 주행 중 | 가림 |

### C03 모드 선택
| 구분 | 내용 |
|---|---|
| 진입 | C02 선택, C01 최근 간 곳, C09 다시 가기 |
| 표시 | 목적지 이름, 카드 3장: 픽업하기 / 그냥가기 / 내려주기 |
| 동작 | 카드 선택 → C04 (모드 전달) |
| 예외 | 승하차 구역이 확인 안 된 시설: 픽업하기 · 내려주기 숨김 |
| 주행 중 | 가림 |

### C04 장소 추천·선택
| 구분 | 내용 |
|---|---|
| 진입 | C03 |
| 표시 | 날씨 띠(예보·강수확률), 후보 2곳 + 추천 이유 한 줄 + 태그(지붕·계단·엘리베이터). 추천 1곳은 기본 선택 |
| 동작 | 후보 선택 → 결정 버튼. 픽업하기 → C05 / 그냥가기 · 내려주기 → 내비 요청 후 C06 |
| 시스템 | [외부] 기상청 단기예보(시설 좌표, 지금~3시간) / [S] 방문 생성(버전 1) / 그냥가기·내려주기: [P] `requestRoute` |
| 예외 | 날씨 못 받음: 띠 대신 "비 와요" 토글을 운전자가 직접 선택 / 서버 실패: 결정 버튼이 "다시 시도" |
| 주행 중 | 가림 |

### C05 링크 전달 QR (픽업하기만)
| 구분 | 내용 |
|---|---|
| 진입 | C04 결정 (픽업하기) |
| 표시 | QR, "운전자 폰으로 찍고 가족에게 링크를 보내 주세요", 픽업 장소 요약 |
| 동작 | 운전자 폰으로 QR 스캔 → 가족에게 링크 공유 / "픽업 장소로 출발" → 내비 요청 후 C06 / "나중에 알리기" → C06 |
| 시스템 | [S] 동승자 링크 발급(24시간) / [P] `requestRoute` 픽업 장소 |
| 예외 | 링크 발급 실패: QR 자리에 "다시 시도" |
| 주행 중 | QR 숨김, 가림 |

### C06 장소 이동
| 구분 | 내용 |
|---|---|
| 진입 | C05 출발, C04 결정(그냥가기 · 내려주기), C12 확인 |
| 표시 | 가는 곳 크게, 내비 상태, 도착 예정(있을 때만). 오른쪽 칸: 픽업하기 = 가족 상태(링크 미확인 / 확인 / 준비됐어요 / 나가는 중), 나머지 = 도착할 때 날씨 |
| 동작 | "도착했어요" → C07 / "위치 바꾸기"(정차 중만) → 픽업하기는 C10, 나머지는 C04로 다시 고르기 |
| 시스템 | [P] `getCurrentLocationInfo` 1분마다 서버로 / [P] `getRouteStateInfo` 도착 예정 [확인] |
| 예외 | 도착 예정이 없거나 오래되면 숨김 / 위치를 못 보내면 동승자 웹에는 "출발했어요"만 / 가족 제안이 오면 C11 |
| 주행 중 | 표시. 장소 · 상태 · "도착했어요"만, "위치 바꾸기" 숨김 |

### C07 도착 완료
| 구분 | 내용 |
|---|---|
| 진입 | C06 "도착했어요" |
| 표시 | 모드별로 화면이 다름<br>C07-1 픽업: "가족이 모두 탔나요?" + 탄 사람 체크(이름 버튼), 가족 상태 카드<br>C07-2 주차: "어디에 세웠나요?" + 층 선택(B1~B4, 선택) → "B2 → 북문 엘리베이터 2분", 날씨 카드<br>C07-3 하차: "가족이 모두 내렸나요?" + "잠깐 정차 구역 · 3분 안에 출발" |
| 동작 | 탑승 완료(모두 체크하면 강조) · 주차 완료 · 하차 완료 → C08 / "아직 기다리는 중" 등 → C06 |
| 시스템 | [S] 방문 종료, 기록 저장(장소·시각·날씨·주차 층), 동승자 링크는 읽기만 가능 → 동승자 웹 W03 |
| 주행 중 | 표시(버튼 하나) |

### C08 장소 평가
| 구분 | 내용 |
|---|---|
| 진입 | C07 완료 버튼 |
| 표시 | "○○ 어땠어요?" (픽업 장소 / 주차장 / 하차 장소), 좋았어요 · 보통 · 별로, 이유 칩 5개(모드별, 여러 개 선택), 이번 방문 요약(날씨·시각·층) |
| 동작 | 점수 선택 → "평가 완료" 활성 → C01 / "건너뛰기" → C01 |
| 시스템 | [S] 평가 저장(점수·이유·날씨) → C09 기록에 표시, 다음 C04 추천 순서에 반영 |
| 예외 | 저장 실패: 홈으로 가고 다음 실행 때 다시 보냄 |
| 주행 중 | 가림(평가는 나중에 C09에서 가능) |

## 위치 변경 (픽업하기만)

M03 위치 변경 흐름 기준. 제안하는 쪽과 받는 쪽 화면은 아래와 같다.

| | 운전자가 제안 | 가족이 제안 |
|---|---|---|
| 버튼 | C06 위치 바꾸기 | W01 위치 바꾸기 |
| 핀 조정 · 응답 대기 | C10 | W04 |
| 받는 화면 | W02 (화면 닫힘 → W06 문자) | C11 |
| 결과 알림 (제안한 쪽) | C12 | W05 (화면 닫힘 → W06 문자) |

**공통 규칙**
| 항목 | 정의 |
|---|---|
| 핀 조정 | 화면 가운데 핀은 고정, 지도를 끌어서 맞춤. 지도 이동이 끝나면 가운데 좌표로 가까운 승하차 지점을 찾음 |
| 승하차 지점 | 확인된 지점 반경 안이면 그 이름 + "확인된 승하차 지점". 아니면 "지도에서 고른 위치 · 차를 세우기 어려울 수 있어요" 경고(보내기는 가능) |
| 보내기 조건 | 기존 핀에서 일정 거리 이상 옮겨야 "여기로 조정하기" 활성 |
| 응답 대기 | 양쪽 지도에 기존 핀(검정) + 제안 핀(주황) + 점선. 한 번에 제안 1개만 |
| 수락 | 기존 핀 삭제, 제안 핀이 만날 곳이 됨(버전 +1). 운전자 내비 다시 요청 |
| 거절 · 10분 무응답 | 제안 핀 삭제, 기존 핀 유지 |
| 취소 | 제안한 쪽이 응답 전에 취소 가능. 받는 쪽 화면에서 제안 핀 삭제 |
| 오래된 응답 | 옛 버전 기준 응답은 서버가 거부 → 최신 상태 표시 |
| 시스템 | [S] 제안 보내기 / 응답 / 취소 / 결과 알림(웹소켓, 끊기면 5초 조회) / [K] 지도·핀 / [P] `requestRoute` 다시 요청(수락 시) |

### C10 위치 바꾸기 (운전자)
| 구분 | 내용 |
|---|---|
| 진입 | C06 위치 바꾸기 (정차 중) |
| 표시 | 왼쪽 지도(기존 핀 "지금" + 가운데 고정 핀 "여기로 바꿀까요?"), 오른쪽: 고른 장소 이름, 확인 여부, 기존 위치에서 거리 |
| 동작 | 지도 끌기 → 핀 위치 조정 / "여기로 조정하기" → 응답 대기 / 대기 중 "제안 취소" → C12-4 / 결과가 오면 C12-1~3 |
| 주행 중 | 지도 잠김, 버튼 "정차 후 조정할 수 있어요" |

### C11 가족 제안 받기 (운전자)
| 구분 | 내용 |
|---|---|
| 진입 | 가족 제안 도착 시 어느 화면에서든 위에 뜸 |
| 표시 | 지도에 기존 핀 + 제안 핀, "기존 → 제안 장소", 가족이 고른 이유, 가족 위치에서 거리 |
| 동작 | "○○으로 바꾸기"(수락) / "○○ 그대로"(거절) → 결과 표시 후 "안내 계속" → C06 |
| 주행 중 | 버튼 숨김, "정차하면 수락·거절할 수 있어요 · 그동안 기존 장소로 안내" |
| 예외 | 10분 동안 응답 없으면 자동으로 그대로 |

### C12 변경 결과 알림 (운전자)
| 구분 | 내용 |
|---|---|
| 진입 | 운전자 제안에 결과가 났을 때, 또는 제안한 쪽이 취소했을 때 |
| 표시 | 위에 큰 알림 띠 + C06 화면<br>C12-1 바뀜(초록): "가족이 수락했어요 · ○○로 바뀌었어요", 목적지에 "바뀐 장소"<br>C12-2 거절(회색): "가족이 기존 장소 그대로 가재요"<br>C12-3 무응답(주황): "가족이 10분 동안 답이 없어요" · 자동 취소, 기존 장소 그대로<br>C12-4 취소(회색): 내가 취소 "바꾸자는 제안을 취소했어요"(가족에게도 알림) / 가족이 취소 "가족이 제안을 취소했어요"(C11이 떠 있었다면 닫힘) |
| 동작 | "확인" → 띠 닫힘, C06 계속 |
| 시스템 | 바뀜일 때 [P] `requestRoute` 새 장소로 |
| 주행 중 | 표시(글자 크게, 버튼 하나) |

## 동승자 모바일 웹

### W01 방문 카드
| 구분 | 내용 |
|---|---|
| 진입 | 초대 링크(유효할 때), W02 · W05 확인 후. 설치·가입 없음 |
| 표시 | 지도(차 위치, 내 위치, 만날 곳 핀, 경로), 도착 예정 크게 · 도착 시각, 진행 막대(출발 → 이동 중 → 도착), 만날 곳 카드(사진·기다릴 위치·지붕) + "위치 바꾸기", 준비 버튼 |
| 동작 | 확대·축소 / 내 위치 · 차 위치 · 전체 보기 / "준비됐어요" ↔ "나가는 중이에요" / "위치 바꾸기" → W04 |
| 시스템 | [S] 웹소켓으로 방문 상태·차 위치 받기(끊기면 5초 조회) / 브라우저 위치는 허용 시에만 |
| 예외 | 위치 권한 거절: 내 위치 없이 표시 / 도착 예정 없음: "차가 오고 있어요"만 / 차 연결 끊김: "차 연결 끊김 · 14:40 기준" / 운전자 제안 도착 → W02 / 운전자 탑승 완료 → W03 |
| 원칙 | 도착 예정이 1분이어도 "도착"으로 바꾸지 않음. 도착은 운전자 "도착했어요"로만 |
