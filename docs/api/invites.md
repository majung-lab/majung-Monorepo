# 문자 초대

## POST /api/visits/{token}/invites

동승자 링크를 문자로 보냅니다. QR 대신 휴대폰 번호로 링크를 전달할 때 씁니다. **운전자 토큰으로만** 호출할 수 있습니다.

> **현재 발송 상태:** 기본 발송 방식(`SMS_PROVIDER=console`)은 개발용입니다. **실제로 문자를 보내지 않고** 서버 터미널에 문자 내용을 출력하기만 합니다. 응답은 성공(200)으로 옵니다. 지금 코드에는 실제 문자 발송 업체 연동이 없고, `SMS_PROVIDER`에 `console` 외의 값을 넣으면 서버가 시작되지 않습니다.

| 규칙 | 내용 |
|---|---|
| 누가 | 운전자만. 동승자 토큰은 403 `FORBIDDEN` |
| 언제 | 방문이 `COMPLETED`·`CANCELLED`가 되기 전, 링크 만료 전 |
| 받는 번호 | 한국 휴대폰 번호(010·011·016·017·018·019)만. 하이픈, 공백, 괄호, 점, `+82`는 허용 |
| 문자 내용 | 서버가 만듭니다. 클라이언트가 내용을 정할 수 없습니다 |
| 번호 저장 | 저장하지 않습니다. 응답과 로그에는 가린 번호만 남습니다 |
| 횟수 제한 | 방문 하나에 **5번**까지. 넘으면 429 `TOO_MANY_INVITES` |
| 재시도 | 같은 `requestId`로 다시 보내면 문자를 다시 보내지 않고 처음 결과를 돌려줍니다 |

- 이 요청은 방문을 바꾸지 않으므로 `version`이 없고, 성공해도 `visit.version`이 오르지 않습니다.
- 재시도 기록과 횟수는 서버 메모리에만 있어서 **서버를 다시 시작하면 초기화됩니다.**
- 같은 `requestId`면 본문이 달라도(번호가 달라도) 처음 결과를 돌려줍니다. 다른 API처럼 `REQUEST_REUSED`가 나지 않습니다.

**요청 본문**

| 필드 | 타입 | 필수 | 제약 | 설명 |
|---|---|---|---|---|
| `requestId` | string | ✓ | 1~128자 | 중복 발송 방지용 고유 값 |
| `phone` | string | ✓ | 1~32자 | 받는 사람 휴대폰 번호 |

```json
{ "requestId": "req-invite-1", "phone": "010-1234-5678" }
```

**보내는 문자**

```
[마중] 예시 쇼핑몰에서 만나요. 링크를 누르면 만날 곳과 차 위치를 볼 수 있어요.
http://localhost:5173/v/<passengerToken>
```

링크 앞부분은 서버 환경 변수 `PASSENGER_WEB_URL`입니다(기본값 `http://localhost:5173`). 휴대폰에서 열려면 PC의 LAN IP나 배포 주소로 설정해야 합니다. 문자에는 동승자 토큰만 들어가고 운전자 토큰은 들어가지 않습니다.

**응답 200:** [InviteResult](models.md#inviteresult)

```json
{ "sentTo": "010-****-5678" }
```

**에러**

| 상태 | code | 원인 |
|---|---|---|
| 400 | `INVALID_REQUEST` | 필수 값 누락, 길이 위반, 정의되지 않은 필드 (예: `text`) |
| 400 | `INVALID_PHONE` | 한국 휴대폰 번호 형식이 아님 (예: `02-123-4567`) |
| 403 | `FORBIDDEN` | 동승자 토큰으로 호출 |
| 404 | `VISIT_NOT_FOUND` | 없는 토큰 |
| 409 | `VISIT_ENDED` | 이미 `COMPLETED`·`CANCELLED`된 방문 |
| 410 | `LINK_EXPIRED` | 만료된 토큰 |
| 429 | `TOO_MANY_INVITES` | 이 방문에서 이미 5번 보냄 |
| 502 | `SMS_FAILED` | 문자 발송 업체 호출 실패. 실패한 요청은 기록되지 않으니 잠시 후 같은 `requestId`로 다시 시도해도 됩니다 |
